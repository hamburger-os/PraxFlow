# Code of Conduct

PraxFlow is an engineering-focused open-source project. We want technical disagreement to be rigorous, evidence-oriented, and respectful.

## Expected behavior

Participants should:

- critique ideas, claims, and evidence rather than people;
- explain disagreement with enough context that others can evaluate it;
- distinguish measured results from inference, preference, or speculation;
- assume good faith while still challenging weak reasoning;
- keep discussions relevant to the issue or pull request;
- respect privacy, confidentiality, and security boundaries;
- make room for contributors with different levels of experience and different technical backgrounds.

## Unacceptable behavior

The following is not acceptable:

- harassment, threats, personal attacks, or discriminatory language;
- sexualized or demeaning content;
- doxxing or sharing private information without permission;
- deliberate disruption, spam, or repeated bad-faith argument;
- publishing security-sensitive information through an inappropriate public channel;
- misrepresenting tests, benchmarks, sources, or other evidence.

Strong technical criticism is welcome. Hostility toward contributors is not.

## Scope

This policy applies to repository issues, pull requests, discussions, reviews, and other project-managed community spaces.

## Enforcement

Maintainers may edit, hide, lock, or remove contributions that violate this policy and may temporarily or permanently restrict participation when necessary.

If a moderation concern cannot safely be raised in public, contact the repository maintainer through an available private GitHub channel. For vulnerability reports, follow [`SECURITY.md`](SECURITY.md).

Maintainers should explain significant moderation actions when doing so would not compromise safety or privacy.
